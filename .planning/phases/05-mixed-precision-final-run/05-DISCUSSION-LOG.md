## Layer Policy — Strategy A (First/Last Layers FP16)

### Sub-question: Identification method

| Option | Description | Selected |
|--------|-------------|----------|
| By layer index | `layer_index == 0` / `layer_index == num_layers - 1` | |
| By layer name | Hardcode from polygraphy inspect output | |
| By layer type | CONVOLUTION for first, SHUFFLE/GATHER for last | |
| Topological I/O tracing | First layer = consumes global input tensor; last = produces global output tensor | ✓ |

**User's choice:** Topological Graph Tracing via I/O Tensors.  
**Notes (user-provided):** Index-based is dangerous — first layer in TRT topological sort is often CONSTANT/SHAPE which crashes the builder if forced FP16. Name/type-based is brittle for a 6-architecture pipeline. Tracing via network's global input/output tensors is robust. Apply FP16 only to mathematically significant layers (exclude CONSTANT, SHAPE).

## Layer Policy — Strategy B (Softmax/LayerNorm Layers FP16)

### Sub-question: LayerNorm identification in TRT graph

| Option | Description | Selected |
|--------|-------------|----------|
| By layer type | `trt.LayerType.SOFTMAX` + type-based LayerNorm detection | |
| Whitelist by name | polygraphy inspect → hardcode exact norm layer names | |
| FP16 for all numerically-sensitive | SOFTMAX + REDUCE + ELEMENTWISE with div/mul | |
| Combined type + name | `SOFTMAX` type OR `"norm" in layer.name.lower()` | ✓ |

**User's choice:** Combined (as agreed earlier in the discussion).  
**Notes:** LayerNorm has no dedicated TRT LayerType — decomposes into primitives (ReduceMean, Sub, Pow, Add, Sqrt, Div, Mul, Add) whose names share `/norm/` substring. Combined approach covers both Softmax (via type) and LayerNorm fragments (via name pattern).
