Entropy, Percentile) — for YOLO11l and YOLO26l, and make the calibration image set

longer overwrite RT-DETR's.

`COCODataLoader(limit=500)` with no seed — `load_calibration_data` then iterates in

calibrator algorithm is the only variable. The executor must confirm whether
`COCODataLoader` selects deterministically (dataset order with a fixed dataset IS
deterministic — same 500 every time) or supports a seed, and ensure the CLI Stage 5 +
Stage 6 paths use the identical deterministic selection. If `COCODataLoader` already
yields a stable first-500 in dataset order, D-08 is satisfied by construction and the
task is to *prove and pin* that with a test; if it shuffles, add a fixed `seed=42`.

The rest is verification: confirm the three calibrators complete for both YOLO graphs,
confirm `int8_best_calibrator.json` is written, confirm Stage 5 metrics land in the
unified results files. Per RESEARCH.md, YOLO11l pure-INT8 mAP drop may exceed 5% (DFL +
C2PSA sensitivity) and YOLO26l <0.5% — large pure-INT8 drops are expected findings, NOT
failures (D-14). This plan does not gate on accuracy; Plan 04 applies the D-14 gate.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| COCO val2017 images → calibration tensors → TensorRT calibrator | 500 operator-provided images are preprocessed into GPU tensors and fed to the TRT INT8 calibrator. |
| Calibration cache file → TensorRT builder | The `.cache` calibration table is read back on subsequent builds and trusted as calibration input. |
| ONNX file → INT8 TRT build | Same YOLO ONNX graph from Plan 01, now compiled with the INT8 builder flag + a calibrator. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Tampering | INT8 calibration `.cache` file reused across builds | accept | The calibration cache is produced locally by this tool and stored in the operator-controlled, `.resolve()`-d `engine_dir`. Plan 01 keyed the cache filename by `model_name` so a YOLO cache cannot be silently substituted for an RT-DETR one. No untrusted-cache ingestion path exists; trusting a locally-built cache is proportionate (ASVS L1, single-user academic tool). |
| T-07-09 | Information Disclosure | Calibration images read from `data/val2017` | accept | COCO val2017 is a public benchmark dataset; the calibration tensors never leave the local process and are not persisted. No PII or sensitive data is involved. |
| T-07-10 | Tampering | YOLO ONNX graph fed to the INT8 builder | mitigate | The ONNX graph was validated with `onnx.checker.check_model` in Plan 01 before any TRT stage; `_build_engine`'s `parser.parse()` guard rejects a malformed graph with a `RuntimeError`. |
| T-07-11 | Denial of Service | INT8 build / calibration exceeding the 8 GB VRAM budget | mitigate | The 2 GB workspace cap (D-06) applies to the INT8 build path; the calibrator uses a fixed batch size of 8 at 640×640 (bounded memory), and `reset_vram_tracking()` clears the CUDA cache between the three calibrator builds so they do not accumulate. The checkpoint verifies no OOM. |
</threat_model>
