<objective>
Verify and lock in Stage 6 — Mixed Precision (INT8 + FP16), Strategy A and Strategy B on
both YOLO11l and YOLO26l — and apply the D-14 phase verification gate.

The CLI orchestration for `6_trt_mixed_a` and `6_trt_mixed_b` already exists in
`cli.py._run_stage`: it reads `int8_best_calibrator.json` (written in Plan 03) to pick
the per-model best calibrator, then builds `TensorRTEngine(precision="int8",
mixed_strategy="a"|"b", ...)` which calls `apply_strategy_a` / `apply_strategy_b` from
`mixed_precision.py`. Plan 01 fixed the mixed-engine filename collision. Plan 03 also
factored the calibration dataloader into a shared `_build_calibration_dataloader()`
helper that the stage-6 branch now uses.

Per D-10 this plan runs the **full 2×2 matrix** — Strategy A and Strategy B on both
models. Per D-13, Strategy B uses the existing Softmax/`"norm"` heuristic in
`mixed_precision.py` **unchanged**: YOLO11/26 are a CNN family (BatchNorm, not
LayerNorm), so the `"norm"` clause is a documented no-op for these models, and the
`LayerType.SOFTMAX` clause is expected to catch YOLO11's DFL + C2PSA attention. **No
YOLO-specific layer-selection logic is added in this phase.**

This plan also owns the **D-14 hard verification gate**: for each model, identify the
**best configuration** across all of Stage 5's INT8 calibrators AND Stage 6's Mixed
Precision strategies, and check whether that best config lands within **2.0%
mAP_50:95** of the model's FP32 baseline. Large *pure-INT8* drops do NOT fail the phase
(D-14) — only the best-config-per-model miss does. If a model's best config still
exceeds 2.0%, the verifier **flags it and stops for a user decision** (D-15) — Strategy
C is NOT auto-triggered.

Per RESEARCH.md D-13: if YOLO11 Strategy B does not beat plain INT8, that is a
**flagged result** to surface in the summary — not an error.

Purpose: Stage 6 is the final optimization stage and the phase's accuracy-recovery
mechanism; the D-14 gate is the phase's success criterion.
Output: Strategy A/B engines for both models, Stage 6 rows in results.csv, the merged
unified Stage 1-6 results file, a Strategy A/B unit test on a YOLO-shaped network, and a
checkpoint that applies the D-14 gate and stops per D-15 if it is missed.
</objective>
