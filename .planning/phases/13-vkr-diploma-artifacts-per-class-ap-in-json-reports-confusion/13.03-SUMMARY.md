## Implementation Notes

### Column Ordering

Headers are: `class_name, n_gt, AP_FP32, AP_TF32, AP_FP16, AP_BF16, AP_INT8_Entropy, AP_INT8_MinMax, AP_INT8_Percentile, AP_Mixed1, AP_Mixed2, min_delta_AP` — 12 columns total. ONNX FP32 is intentionally omitted per CONTEXT.md.

### n/a Placement Strategy

For RF-DETR-L: the 5 excluded stages (`5_trt_int8_entropy`, `5_trt_int8_minmax`, `5_trt_int8_percentile`, `6_trt_mixed_a`, `6_trt_mixed_b`) are written as the string `n/a` in both CSV and Markdown. The `min_delta_AP` computation skips these cells, using only the 4 valid non-FP32 stages (TF32, FP16, BF16) for the delta calculation.

### BOM and Lineterminator Decisions

- **CSV**: `path.open("w", encoding="utf-8-sig", newline="")` writes the UTF-8 BOM (`\xef\xbb\xbf`) automatically via Python's `utf-8-sig` codec. `lineterminator="\n"` ensures `\n`-only endings regardless of platform — required for sha256 stability across Windows/Linux.
- **Markdown**: `path.write_text(content, encoding="utf-8")` — no BOM, plain UTF-8. Content assembled with `"\n".join(lines) + "\n"`.

### min_delta_AP Semantics

`min_delta_AP` = `min(AP_stage - AP_FP32)` across all numeric (non-`n/a`) stages excluding the FP32 baseline itself. This captures the WORST observed accuracy drop for that class. Negative value = accuracy degraded vs FP32. Positive value = accuracy improved (possible for BF16/TF32 due to numerical rounding). Formatted to 3 decimal places.

## Output Files Status

The 16 output files (8 CSV + 8 Markdown) are NOT generated in this plan because the stage JSONs have not yet been backfilled with `per_class_ap` data. The script correctly detects this and exits with code 2 and the message:

```
[ERROR] rt-detr: FP32 baseline missing or not backfilled — run scripts/build_per_class_ap.py first
```

The files will be generated once the user runs `scripts/build_per_class_ap.py --live --limit 5000` (Mode B, requires ~24h GPU time) or Mode A after the cache is populated.
