# Phase 5: Mixed Precision & Final Run - Context

**Gathered:** 2026-05-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Implement Strategy A and Strategy B mixed precision TensorRT engines (selective FP16 layers
over an INT8 base) using the best INT8 calibrator identified from Phase 4. Register both as
runnable benchmark stages (`6_trt_mixed_a`, `6_trt_mixed_b`), run the full 8-stage pipeline
end-to-end, and produce diploma-ready output: unified results CSV/JSON + human-readable
`summary.txt` and `summary.md` tables generated by `benchmark merge`.

<decisions>
## Implementation Decisions

### Best Calibrator Selection (MIX-03)
- **D-01:** At runtime, read `results/{model}/{run_id}/int8_best_calibrator.json` → field
  `best_calibrator` (e.g., `"entropy"`). Pass this value as `calibrator_method` to the
  mixed precision engine builder.
  - If the file does not exist in the current `run_id` directory → fallback to `"entropy"` +
    emit `logger.warning("int8_best_calibrator.json not found in run {run_id} — defaulting to entropy")`.
  - `run_id` is the same across all stages in a single `benchmark run` command invocation
    (created once in `ResultLogger` at CLI startup, shared by the stage loop). No separate
    flag needed — mixed stages naturally share the `run_id` of the INT8 stages when launched
    together, e.g.: `benchmark run --model rt-detr --stage 5_trt_int8_minmax,5_trt_int8_entropy,5_trt_int8_percentile,6_trt_mixed_a,6_trt_mixed_b`

### Layer Policy — Strategy A (MIX-01)
- **D-02:** Use **Topological Graph Tracing via I/O Tensors** — do NOT use layer indices
  (`layer_index == 0`) as the first TRT layer is often CONSTANT/SHAPE which crashes the builder.
  Implementation:
  1. Collect names of all network global input tensors (`network.get_input(i).name`)
     and output tensors (`network.get_output(i).name`).
  2. Iterate all layers. A layer is a "first layer" if it consumes any global input tensor;
     a "last layer" if it produces any global output tensor.
  3. Apply `layer.precision = trt.float16` and `layer.set_output_type(0, trt.float16)`
     **only** for mathematically significant layers (exclude `trt.LayerType.CONSTANT`,
     `trt.LayerType.SHAPE`) to avoid builder crashes.
  4. All remaining layers → INT8 (inherited from the base INT8 config + calibrator).

### Layer Policy — Strategy B (MIX-02)
- **D-03:** Use **combined type + name matching** to identify FP16-sensitive layers:
  - `layer.type == trt.LayerType.SOFTMAX` → FP16
  - `"norm" in layer.name.lower()` → FP16 (covers LayerNorm fragments:
    `/norm/`, `/layernorm/`, `/layer_norm/` naming conventions in ONNX-exported graphs)
  - All other layers → INT8.
  Rationale: LayerNorm has no dedicated TRT LayerType — it decomposes into ReduceMean,
  Sub, Pow, Add, Sqrt, Div, Mul, Add primitives whose names share the `/norm/` substring.

### Code Structure
- **D-04:** Mixed precision layer logic lives in a **new file**
  `src/benchmark/engines/mixed_precision.py` — symmetric to `int8_calibrators.py`.
  Public API:
  ```python
  def apply_strategy_a(network: trt.INetworkDefinition) -> int: ...  # returns count of FP16 layers
  def apply_strategy_b(network: trt.INetworkDefinition) -> int: ...  # returns count of FP16 layers
  ```
  Called from `TensorRTEngine._build_engine()` after INT8 calibration config is applied.

- **D-05:** `TensorRTEngine` API extension — add `mixed_strategy: Literal['a', 'b'] | None = None`
  parameter (alongside existing `calibrator_method`). When `mixed_strategy` is set:
  `precision` must be `'int8'` and `calibrator_method` must be non-None (resolved from
  `int8_best_calibrator.json` before engine construction). Mixed precision = INT8 base +
  per-layer FP16 overrides from `mixed_precision.py`.

### Stage IDs & File Naming
- **D-06:** Stage IDs: `6_trt_mixed_a` / `6_trt_mixed_b`. Added to `STAGE_REGISTRY` in
  `cli.py` after `5_trt_int8_percentile`. Consistent with CLAUDE.md §«Stage 6: Mixed
  Precision Quantization (INT8 + FP16)».

- **D-07:** Engine file naming: `engines/{model}_mixed_{strategy}_{calibrator}.engine`
  Examples:
  - `engines/rtdetr_mixed_a_entropy.engine`
  - `engines/rtdetr_mixed_b_entropy.engine`
  Encodes model, strategy, and calibrator for full traceability.

### Final Run Output (diploma-ready)
- **D-08:** `benchmark merge --model rt-detr` generates **both**:
  - `results/{model}/{run_id}/summary.txt` — plain-text tabulate table (terminal-friendly)
  - `results/{model}/{run_id}/summary.md` — Markdown table (diploma/README-ready)
  Columns: Stage | Latency ms | FPS | mAP@50 | mAP@50:95 | AccDrop% | VRAM MB | Model MB

- **D-09:** Best INT8 calibrator is marked with `★` in the Stage column of both summary
  files. No separate `6_trt_int8_best` row in unified CSV — data is not duplicated.

### Claude's Discretion
- **`--force-rebuild` for mixed engines** — same semantics as Phase 3/4: delete existing
  `.engine` file and rebuild from scratch. No separate cache file for mixed precision
  (calibration cache is shared with the base INT8 engine of the same calibrator method).
- **FP16 layer count logging** — `apply_strategy_a/b` returns the count of layers set to
  FP16. Log this at INFO level: `"Strategy A: {n} layers set to FP16"` for scientific
  reproducibility in diploma appendix.
- **Error handling for mixed build failure** — same pattern as BF16 (Phase 3 D-05/D-06):
  write `BenchmarkResult` with `skipped_reason='Mixed precision build failed: {exc}'`,
  all numeric metrics `NaN`. Pipeline continues to next stage.

</decisions>

## Existing Code Insights

### Reusable Assets
- `TensorRTEngine` (`src/benchmark/engines/tensorrt_engine.py`) — extend in-place. Add
  `mixed_strategy: Literal['a','b'] | None = None` param. `_build_engine()` is the
  injection point: after INT8 config is applied, call `apply_strategy_a/b(network)`.
- `ResultLogger.save_int8_best_calibrator(model)` (`src/benchmark/utils/logger.py`) — already
  writes `int8_best_calibrator.json` after INT8 stages. Phase 5 reads this file at the
  start of mixed stage execution. The `run_id` is already shared via `ResultLogger` instance.
- `COCODataLoader` — reuse with `limit=500, shuffle=False` for the calibration pass inside
  mixed precision builds (same as INT8 calibrators in Phase 4).
- `BenchmarkResult.skipped_reason` field — already exists (Phase 3 D-06). Use for mixed
  build failures.

### Established Patterns
- Engine lazy-build: check `.engine` exists → load; else build → serialize. Apply same to
  mixed engines with key `engines/rtdetr_mixed_{strategy}_{calibrator}.engine`.
- VRAM tracking: `torch.cuda.reset_peak_memory_stats()` before run,
  `torch.cuda.max_memory_allocated()` after — identical to all prior engines.
- CUDA sync: `torch.cuda.synchronize()` at each timing boundary.
- TRT workspace: `config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 2 << 30)` —
  applied to ALL builds including mixed precision.
- Stage loop in `cli.py`: comma-separated `--stage` parsing already supports multi-stage
  runs with shared `run_id` (lines 277–283). Mixed stages participate transparently.

### Integration Points
- `STAGE_REGISTRY` in `cli.py` — append `"6_trt_mixed_a"`, `"6_trt_mixed_b"` after
  `"5_trt_int8_percentile"` so `--all-stages` includes them.
- `_run_stage()` — add `elif stage in ("6_trt_mixed_a", "6_trt_mixed_b"):` branch that:
  1. Reads `int8_best_calibrator.json` from `result_logger`'s run directory
  2. Constructs `TensorRTEngine(precision='int8', calibrator_method=best_cal, mixed_strategy='a'/'b')`
  3. Passes calibration dataloader to `engine.load_model()`
- `ResultLogger.merge_to_unified()` — extend to generate `summary.txt` and `summary.md`
  in addition to existing unified CSV/JSON. Mark best INT8 row with `★` in Stage column.
- `engines/__init__.py` — export `apply_strategy_a`, `apply_strategy_b` from
  `mixed_precision.py` if needed by CLI or tests.
