Create `scripts/realtime_demo.py` — typer CLI that produces annotated MP4s.

**Module-level setup:**
- `from __future__ import annotations`
- `import cv2`, `import numpy as np`.
- `np.random.seed(0); random.seed(0)` at module load.
- Module-level logger.
- Hardcoded constants for the 3 required runs (decided at script load by inspecting the existing JSONs):

```
DEMO_INPUT_DEFAULT: Path = Path("data/demo.mp4")
OUT_DIR_DEFAULT: Path = Path("media/video")

# Bbox drawing style — identical to P04 (qualitative examples)
BBOX_COLOR_BGR: tuple[int, int, int] = (255, 100, 0)
BBOX_THICKNESS: int = 2
BBOX_OPACITY: float = 0.7
CONFIDENCE_THRESHOLD: float = 0.25

# FPS overlay
FPS_WINDOW: int = 30   # rolling average over 30 frames
```

**Helper functions:**

- `_select_rt_detr_best_mixed(results_root: Path) -> str`:
  - Loads `results/rt-detr/quant/6_trt_mixed_a.json` and `6_trt_mixed_b.json`.
  - Returns the stage string with higher `map_50_95`. Tie-break: alphabetical (`6_trt_mixed_a` wins on equality).

- `_select_fastest_yolo(results_root: Path) -> tuple[str, str]`:
  - For each YOLO model in `("yolo11l", "yolo26l")` and each mixed stage in `("6_trt_mixed_a", "6_trt_mixed_b")`: load the JSON, read `throughput_fps`.
  - Return `(model, stage)` with the highest `throughput_fps`. Tie-break: alphabetical on `f"{model}_{stage}"`.
  - **Acceptance criterion (missing JSON handling):** If a YOLO model's JSON for stage Mixed-A or Mixed-B is MISSING on disk OR `throughput_fps` is absent / non-numeric, log a warning at WARN level via the module logger (`logger.warning("Skipping %s/%s: <reason>", model, stage)`) and skip that candidate. If ALL 4 candidates (yolo11l Mixed-A/B + yolo26l Mixed-A/B) are skipped, exit with `typer.Exit(code=2)` and a clear error message naming the missing JSONs.

- `_build_engine(model: str, stage: str) -> BaseEngine`:
  - Dispatch IDENTICAL to `src/benchmark/cli.py::run` (lines ~150-320, the big `if/elif` over `stage`):
    - Stage `1_pytorch_fp32` → `PyTorchEngine(model_name=model, adapter=_get_adapter(model))`, then `engine.load_model(Path(MODEL_REGISTRY[model]["weights"]))`.
    - Stage `2_onnx_fp32` → `OnnxRuntimeEngine(model_name=model, onnx_path=Path(MODEL_REGISTRY[model]["onnx"]), adapter=_get_adapter(model), input_size=(640, 640))`, then `engine.load_model(onnx_path)`.
    - TRT stages → `TensorRTEngine(model_name=model, precision=<derived>, engine_dir=Path("engines"), adapter=_get_adapter(model), force_rebuild=False)`. **Engine path convention (verified in `src/benchmark/engines/tensorrt_engine.py:117-154`):** `TensorRTEngine` derives its own engine filename inside its `__init__` from `(model_token, precision)`/calibrator-method/mixed-strategy and stores it as `self._engine_path = engine_dir / "{model_token}_{precision}.engine"` (or `_int8_{calibrator_method}.engine`, or `_mixed_{strategy}_{calibrator_method}.engine`). The caller only passes `engine_dir=Path("engines")` and `precision=<derived from stage>` — DO NOT reconstruct the engine filename manually. Reuse the `precision_map` / `cal_method_map` / `mixed_strategy_map` dispatch from `cli.py::run` verbatim. Then call `engine.load_model(Path(MODEL_REGISTRY[model]["onnx"]))` (TRT load is a no-op when the cached `.engine` file already exists; otherwise it triggers a rebuild — for P06 we EXPECT all engines to exist on disk, so the load is a cache hit).
  - If `MODEL_REGISTRY[model]["weights"]` / `["onnx"]` is missing, OR the `.engine` file the constructor expects does not exist on disk: log a clear error naming the missing path and raise `typer.Exit(2)`.

- `_run_one(model: str, stage: str, input_video: Path, out_dir: Path) -> Path`:
  - `engine = _build_engine(model, stage)`.
  - `cap = cv2.VideoCapture(str(input_video))`.
  - `fps_in = cap.get(cv2.CAP_PROP_FPS)` (use 30 if NaN/0).
  - `w = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH)); h = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))`.
  - `fourcc = cv2.VideoWriter_fourcc(*"mp4v")`.
  - Output filename: `out_dir / f"{model}_{stage}.mp4"`.
  - `writer = cv2.VideoWriter(str(out_path), fourcc, 30.0, (w, h))` (30 FPS per CONTEXT.md).
  - Rolling FPS window: `frame_times = collections.deque(maxlen=FPS_WINDOW)`.
  - Per-frame loop:
    1. `ok, frame = cap.read()`; break on False.
    2. `t0 = time.perf_counter()`.
    3. Convert `frame` (BGR ndarray) into a `COCOSample`-compatible object — the engines expect a `COCOSample`. Build a synthetic sample with `image=cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)`, `image_id=-1`, `original_size=(h, w)`, and an empty `COCOAnnotation`.
    4. `inputs = engine.preprocess(sample); raw = engine.infer(inputs); det = engine.postprocess(raw, sample)`.
    5. `t1 = time.perf_counter()`; `frame_times.append(t1 - t0)`.
    6. Draw boxes on `frame` (BGR) using the same opacity+stroke pattern from P04: `cv2.addWeighted` for the translucent overlay, then a non-translucent stroke. Filter `det.scores >= CONFIDENCE_THRESHOLD`. Label each box with `f"{class_name} {score:.2f}"` (resolve class_name from a hardcoded COCO-91 name table loaded once at script start from `instances_val2017.json::categories`).
    7. Overlay top-right rolling FPS: `fps_now = len(frame_times) / sum(frame_times)` (guard against division by zero); render with `cv2.putText` at coords `(w - 120, 30)`, white text with black outline.
    8. Overlay bottom-left model/mode label: `f"{model} / {stage}"` at coords `(10, h - 15)`, white text with black outline.
    9. `writer.write(frame)`.
  - `cap.release(); writer.release()`.
  - Return `out_path`.
