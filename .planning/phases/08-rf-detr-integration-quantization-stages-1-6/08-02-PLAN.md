<objective>
Create the Stage 2 (ONNX FP32) ONNX export pipeline for RF-DETR-Large, then run the
Stage 2 ONNX Runtime benchmark.

**Per the researcher's locked recommendation (D-RF-02 = path (a))**: use the
vendor's `rfdetr.export()` API (which internally calls `torch.onnx.export(...,
dynamo=False, do_constant_folding=True, keep_initializers_as_inputs=False)` and
emits the model's `forward_export` mode with output names `["dets", "labels"]`),
followed by the project's mandatory `simplify_onnx()` step (C-10 — overrides any
vendor "already simplified" claim; the vendor's own `simplify` kwarg is a
deprecated no-op since `rfdetr==1.6`). The alternative — manually replicating
LWDETR's `forward = forward_export` swap + custom `nn.Module` wrapper + manual
`torch.onnx.export` — was rejected by the researcher as strictly more code and
risk for no benefit.

**Locked decisions reflected in this plan:**
- **D-RF-02 (researcher-recommended, planner-locked):** path (a) — `RFDETRLarge().export(opset_version=18, shape=(704, 704))` + project `simplify_onnx()`.
  - Opset 18 (not the vendor default 17) — matches the project transformer
    convention; `onnx_export.py` defaults `opset_version=18` for RT-DETR and the
    same applies to RF-DETR per RESEARCH § "D-RF-02 Investigation".
  - Shape (704, 704) per D-RF-04 (vendor default; matches PE=44 = 704/16 baked
    into `rf-detr-large-2026.pth`).
- **C-10 (carried from Phase 7):** mandatory `simplify_onnx()` step — runs even
  though the vendor exporter already produces a clean graph. The vendor's
  `simplify` kwarg is a deprecated no-op (since 1.6) and explicitly logs a
  warning + ignores it; the project's `simplify_onnx()` is the authoritative
  simplifier.
- **Landmine #1 (mitigated in this plan):** vendor `RFDETR.export()` is
  destructive — `LWDETR.export()` swaps `self.forward = self.forward_export`
  in-place. The export script instantiates -> exports -> exits, ensuring the
  destructive mutation never affects another consumer. Plan 08-01's Stage 1
  baseline uses a separate `RFDETRLarge()` instance.
- **Landmine #8 (handled in Plan 08-01's adapter — no plan-02 code needed):**
  the exported ONNX has outputs in the order `[dets (=boxes,(N,4)), labels
  (=logits,(N,91))]` — OPPOSITE of RT-DETR's `[logits, pred_boxes]`. The
  adapter's `parse_outputs` already detects by SHAPE not INDEX (Plan 08-01
  Task 1).

**Architecture verification (researcher confirmed this in 08-RESEARCH.md and
PATTERNS.md):**
- `src/benchmark/engines/onnx_engine.py` is ALREADY adapter-aware — it delegates
  preprocess to `adapter.preprocess(...)` and parse_outputs to
  `adapter.parse_outputs(...)`. No engine code change is needed for RF-DETR.
- `src/benchmark/engines/onnx_export.py` has `simplify_onnx()` and
  `validate_onnx()` functions; we call them from the new export script. No
  engine code change.
- The expected simplified graph (verified live in this session per RESEARCH
  § "ONNX Graph Inspection"): 1701 -> 918 nodes (-46%), 51 LayerNormalization
  preserved, 20 Softmax preserved, 0 ReduceMean / 0 Pow (no decomposed
  LayerNorm — the precondition for Plan 08-04's Strategy B). Output shapes
  `dets: [1, 300, 4]`, `labels: [1, 300, 91]`. File size ~123 MB -> ~120 MB.

Purpose: Without a simplified ONNX in `weights/rfdetr-l/rfdetr_l_sim.onnx`,
Plans 08-03 (TRT TF32/FP16/BF16) and 08-04 (INT8 + Mixed Precision) cannot
build engines. Stage 2 also produces the Stage 2 ORT metric row that the
diploma's Stage-2 column depends on (OPT-TR-01).

Output: `scripts/export_rfdetr_onnx.py` script, the simplified ONNX file at the
project-convention path, a Stage 2 ORT benchmark row in `results.csv`, and unit
test coverage for the export script's call pattern.
</objective>
