<decisions>
## Implementation Decisions

### Hardware Info Schema (LOG-12)
- **D-01:** Add flat hardware columns to `BenchmarkResult`: `hw_gpu: str`, `hw_cuda_version: str`, `hw_driver_version: str`, `hw_trt_version: str`. Repeated in every row — pandas-friendly, no file joins required for diploma analysis.
- **D-02:** `hw_trt_version` is empty string `""` for stages 1–2 (TRT not installed). Never `None` or `"N/A"` — keeps CSV schema consistent across all stages.
- **D-03:** Hardware info collected **once at CLI startup** via a `HardwareInfo.collect()` call, injected into `ResultLogger`. Zero per-run overhead, no drift between measurements.

### Per-stage File Naming (LOG-10, LOG-11)
- **D-04:** Stage identifier pattern: `<stage_num>_<engine>_<precision_or_strategy>`. Examples:
  - `1_pytorch_fp32`
  - `2_onnx_fp32`
  - `3_trt_tf32`
  - `4_trt_fp16` / `4_trt_bf16`
  - `5_trt_int8_minmax` / `5_trt_int8_entropy` / `5_trt_int8_percentile`
  - `6_trt_mixed_strategy_a` / `6_trt_mixed_strategy_b`
  
  This pattern lexicographically sorts in pipeline order — no mapping table needed in pandas.
- **D-05:** Per-stage files stored at `results/{model_name}/{stage_name}.csv` and `results/{model_name}/{stage_name}.json`. One CSV + one JSON per stage per model run.
- **D-06:** Unified file at `results/results.csv` and `results/results.json` — `stage` column uses the same `<stage_num>_<engine>_<precision>` string. Generated by `benchmark merge` CLI command (CLI-03).

### MACs/FLOPs Computation (LOG-09)
- **D-07:** Strategy pattern — route by model family:
  - **YOLO family (Ultralytics):** Use native `model.info()` or internal `utils.autobatch` to extract FLOPs. No third-party profiler.
  - **DETR family (HuggingFace / PyTorch-native):** Use `calflops.calculate_flops(model, input_shape=(1,3,640,640))`.
- **D-08:** If `calflops` reports unsupported operations (e.g., `MultiScaleDeformableAttention` C++ extensions count as 0 FLOPs), emit `logger.warning("calflops: unsupported ops detected — MACs may be underestimated for %s", model_name)`. Custom hooks for deformable attention are a future enhancement, not Phase 2 scope.
- **D-09:** MACs computed **once at stage 1 (PyTorch)**. The same value is passed through and reused in stages 2–6. MACs are model-invariant — the computation graph doesn't change with precision or runtime.

### COCO Evaluation Metrics / IoU (LOG-06)
- **D-10:** Log all 12 COCO eval stats as **named, typed fields** in `BenchmarkResult`. No `dict` field — explicit fields keep CSV schema self-documenting and type-checker happy.
- **D-11:** New fields replacing the current 2-field accuracy section:
  ```
  map_50: float         # AP @ IoU=0.50
  map_75: float         # AP @ IoU=0.75  (new)
  map_50_95: float      # AP @ IoU=0.50:0.95
  map_small: float      # AP, area=small  (new)
  map_medium: float     # AP, area=medium (new)
  map_large: float      # AP, area=large  (new)
  ar_1: float           # AR @ maxDets=1  (new)
  ar_10: float          # AR @ maxDets=10 (new)
  ar_100: float         # AR @ maxDets=100 (new)
  ar_small: float       # AR, area=small  (new)
  ar_medium: float      # AR, area=medium (new)
  ar_large: float       # AR, area=large  (new)
  ```
  Populated from `COCOeval.stats[0:12]` in `evaluate_accuracy()`.

### OnnxRuntimeEngine (deferred from Phase 1)
- **D-12:** Implement `OnnxRuntimeEngine` in `src/benchmark/engines/onnx_engine.py`. Follows the same `BaseEngine` abstract contract as `PyTorchEngine`. Uses `onnxruntime-gpu` with CUDA execution provider. Enables stage 2 benchmarking end-to-end.

### CLI Design (CLI-01, CLI-02, CLI-03)
- **D-13:** Entry point via `typer` (already a dependency). Command: `benchmark`.
  - `benchmark run --model rt-detr --stage 1_pytorch_fp32` — single stage (CLI-01)
  - `benchmark run --model rt-detr --all-stages` — all 6 stages sequentially (CLI-02)
  - `benchmark merge --model rt-detr` — merge per-stage files → unified results.csv (CLI-03)
- **D-14:** `--limit N` flag on `run` for development (subset of COCO val2017). Default: full 5000 images.
- **D-15:** `--output-dir PATH` flag. Default: `results/`.
- **D-16:** CLI configures root logging at `INFO` level (no-op in library code per existing convention).

</decisions>

<specifics>
## Specific Ideas

- **Stage string is the canonical identifier everywhere** — same `1_pytorch_fp32` value used in: `stage` CSV column, per-stage filename stem, and CLI `--stage` argument. No translation layer needed.
- **calflops unsupported-ops warning** — critical for future `MultiScaleDeformableAttention` (D-FINE, RF-DETR): those C++ extension ops report 0 FLOPs in calflops. The warning surfaces this silently-wrong value. Custom hooks are Phase 4+ scope.
- **MACs are not re-measured for ONNX/TRT engines** — stored as baseline metadata. The stage's CSV records the PyTorch-computed MACs value for all stages of the same model.
- **12 COCO stats map directly to `COCOeval.stats[0:12]`** — `map_50=stats[1]`, `map_75=stats[2]`, `map_50_95=stats[0]`, `map_small=stats[3]`, `map_medium=stats[4]`, `map_large=stats[5]`, `ar_1=stats[6]`, `ar_10=stats[7]`, `ar_100=stats[8]`, `ar_small=stats[9]`, `ar_medium=stats[10]`, `ar_large=stats[11]`.

</specifics>
