<objective>
Implement the Stage 1 foundation for RF-DETR-Large: a `RFDETRAdapter` that conforms to
the project's `ModelAdapter` protocol, the CLI registry/dispatch wiring that lets
`benchmark run --model rfdetr-l --stage 1_pytorch_fp32` execute, and a small CLI fix
so `compute_macs` reads the input shape from the adapter instead of the hardcoded
`(640, 640)` (required because RF-DETR runs at 704x704 per D-RF-04).

This is the **only plan in Phase 8 that creates net-new source code**. Plans 02-04
are CLI invocations + a 2-line patch to `mixed_precision.py` (08-04). Per the
research (08-RESEARCH.md, HIGH confidence): the rest of the optimization pipeline
(`OnnxRuntimeEngine`, `TensorRTEngine`, `int8_calibrators`, `mixed_precision`) is
already adapter-aware and needs no changes.

**Per CONTEXT.md decisions:**
- **D-RF-01 (locked):** Use `rfdetr.RFDETRLarge` (33.9 M params, 704x704, DINOv2 +
  DETR decoder, Apache 2.0). Symmetrical to YOLO11l/26l "L" variant choice.
- **D-RF-04 (researcher-recommended, planner-locked):** Keep vendor default 704x704;
  640 is config-valid but breaks the vs-paper AP_50:95=56.5 baseline. Phase 9 export
  tables will carry an `input_resolution` column (deferred — do NOT widen this phase).
- **C-03 (carried from Phase 7):** TF32 forced off for the FP32 baseline. This is
  already enforced inside `PyTorchEngine.load_model` (sets
  `torch.backends.cuda.matmul.allow_tf32 = False`); no adapter-level change needed.
- **C-09 (carried from Phase 7):** All metrics flow through `ResultLogger` —
  per-stage CSV/JSON and the unified `results.csv`/`results.json` (`model_name`,
  `stage` columns). No new logger code; Stage 1 reuses the existing pipeline.

**Critical RF-DETR-vs-RT-DETR diffs the executor MUST internalize** (from RESEARCH
+ PATTERNS):
1. **Output ordering by shape, not index** (Landmine #8): RF-DETR ONNX outputs
   `[dets (=boxes,(N,4)), labels (=logits,(N,91))]`; RT-DETR outputs
   `[logits, pred_boxes]`. The adapter's `parse_outputs` MUST detect by shape — if
   `raw_outputs[0].shape[-1] == 4` then `raw_outputs[0]` is boxes; else it is
   logits. RT-DETR's index-based code (`raw_outputs[0]` = logits) is WRONG for
   RF-DETR.
2. **COCO-91 direct mapping** (no LUT): index 0 = N/A (no COCO id=0), indices 1..89
   = COCO-91 IDs sparse, index 90 = background. Filter `class_idx != 0 &
   class_idx != 90`, emit `class_idx` directly as the COCO-91 `category_id`. NO
   `_COCO80_LUT` array.
3. **Top-k over flattened (queries x classes)**, NOT per-query argmax (vendor
   postprocess.py:27-80): same query can contribute multiple detections at
   different classes.
4. **Positional model call**: RF-DETR's LWDETR takes a single positional tensor
   (`model(inputs)`), not HF kwarg style (`model(pixel_values=inputs)`).
5. **Preprocess in adapter** (mirrors YOLO, NOT RT-DETR): RT-DETR has no
   `preprocess()`; RF-DETR owns its preprocess (direct stretch resize to 704x704 +
   ImageNet normalize). DINOv2 needs patch-aligned direct resize, NOT
   YOLO-letterbox.
6. **Vendor weight download side-effect**: `RFDETRLarge()` downloads
   `rf-detr-large-2026.pth` (~150 MB, ~30-60 s) on first call into vendor cache.
   Subsequent calls hit the cache (Landmine #6). The `weights/rfdetr-l/` directory
   exists only to keep per-model layout uniform.

Purpose: Without `RFDETRAdapter` no Stage 2-6 RF-DETR command works (the CLI cannot
resolve `--model rfdetr-l` and the ONNX/TRT engines cannot get adapter-driven
preprocess). Without the `compute_macs` fix, Stage 1 measures FLOPs on the wrong
input shape and the diploma's MACs column is wrong for RF-DETR.

Output: `RFDETRAdapter` class, CLI registry/dispatch wiring, adapter-driven
`compute_macs`, unit-test coverage for the four parse_outputs subtleties, and a
GPU checkpoint that runs Stage 1 end-to-end and confirms a non-zero mAP appears in
`results.csv`.
</objective>

    **`parse_outputs(self, raw_outputs: object, original_size: tuple[int, int], input_size: tuple[int, int], score_threshold: float) -> Detection`**:
    use the algorithm verbatim from RESEARCH lines 363-415. Three structural
    rules the executor MUST follow:

    (a) **Input-format dispatch with output-order detection by SHAPE not INDEX**
        (Landmine #8 — RF-DETR ONNX/TRT outputs `[dets, labels]` which is OPPOSITE
        of RT-DETR's `[logits, pred_boxes]`). For `isinstance(raw_outputs, dict)`
        (PyTorch path): `logits = raw_outputs["pred_logits"][0]` (-> (300, 91)),
        `boxes_norm = raw_outputs["pred_boxes"][0]` (-> (300, 4)). For
        `isinstance(raw_outputs, (list, tuple))` (ONNX/TRT path): unpack
        `a, b = raw_outputs[0][0], raw_outputs[1][0]`; **detect by shape** — if
        `a.shape[-1] == 4` then `boxes_norm = torch.from_numpy(a); logits =
        torch.from_numpy(b)`; else `logits = torch.from_numpy(a); boxes_norm =
        torch.from_numpy(b)`. Else raise `TypeError` via the project's
        `msg = "..."; raise TypeError(msg)` ruff EM101 pattern.

    (b) **Topk over flattened (queries x classes)**, NOT per-query argmax:
        `probs = logits.sigmoid()` (-> (300, 91)); `flat = probs.view(-1)`
        (-> (300*91,)); `topk_vals, topk_idx = torch.topk(flat, _NUM_QUERIES)`;
        `query_idx = topk_idx // probs.shape[1]`; `class_idx = topk_idx %
        probs.shape[1]`.

    (c) **Filter `class_idx == 0` AND `class_idx == _BG_INDEX`** (drop the N/A slot
        AND the DETR background slot before COCOeval sees the results) AND the
        score threshold: `keep = (topk_vals >= score_threshold) & (class_idx != 0)
        & (class_idx != _BG_INDEX)`. NO COCO-80 LUT — `labels =
        class_idx[keep].cpu().numpy().astype(np.int64)` IS the COCO-91 category_id
        array.

    Then gather `sel_boxes = boxes_norm[query_idx[keep]]`, denormalize cx,cy,w,h
    to original-pixel xyxy (same math as RT-DETR adapter lines 274-281: `orig_h,
    orig_w = original_size`; `cx, cy, w, h = sel_boxes.unbind(-1)`; `x1 = (cx -
    w/2) * orig_w` etc.; `boxes_xyxy = torch.stack([x1,y1,x2,y2],
    dim=-1).cpu().numpy().astype(np.float32)`), and return
    `Detection(boxes=boxes_xyxy.reshape(-1, 4), scores=scores, labels=labels)`
    where `scores = topk_vals[keep].cpu().numpy().astype(np.float32)`. The
    `.reshape(-1, 4)` is the same empty-array safety used in RT-DETR.

    The `input_size` parameter is unused (boxes are normalized to [0,1]); mark
    with `# noqa: ARG002` per RT-DETR convention.
